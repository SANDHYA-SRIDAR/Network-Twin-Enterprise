# NetTransform ML Dataset & Scenario Generator

## 1. Overview & Provenance
This directory contains the dataset generation script and pre-generated scenario dataset for the NetTransform ML and NSGA-II pipeline:

- `generate_dataset.py`: Standalone script for generating random enterprise topologies, failure scenarios, synthetic telemetry time series, and NSGA-II recovery frontiers.
- `data/dataset_600_scenarios.zip`: Archived 600-scenario dataset containing `scenarios.csv`, `telemetry_links.csv`, `telemetry_nodes.csv`, and `pareto_fronts.csv`.

> **Honest Labeling Notice**: All rows across all generated CSV tables carry `provenance="simulated"`. This is synthetic, modeled telemetry generated through analytical simulation and mathematical noise models, not live physical network device data.

## 4. Regeneration Commands
As specified in `generate_dataset.py` docstring:

```bash
# Random enterprise topologies
python generate_dataset.py --scenarios 400 --telemetry 60 --recovery 150 --seed 7 --out data

# User saved topology (NetworkDefinition JSON)
python generate_dataset.py --topology my_topology.json --scenarios 200 --out data_mine
```

## 5. Dependency Note & Execution Status
- `generate_dataset.py` imports two external modules:
  - `nettwin_engine`: (`Flow`, `Link`, `Topo`, `evaluate`, `single_link_vulnerability`, `logical_graph`)
  - `nsga2`: (`run_nsga2`, `pareto_front`)
- **Repository Search Result**: Neither `nettwin_engine` nor `nsga2` exists in this repository. The main application uses `app.engines.analytical_simulator` (`analytical-network-sim/2.1`) and `app.engines.optimization` (backed by `pymoo`).
- In accordance with project instructions, `generate_dataset.py` was copied byte-for-byte without stubbing or adapting it, and was **not executed**.

## 6. Engine Divergence Warning
> **Warning**: The dataset in `data/dataset_600_scenarios.zip` was generated by a separate external engine (`nettwin_engine`), not the in-repo `analytical-network-sim/2.1` engine. Simulation assumptions, queuing models, and numerical values will differ from results computed by the application's FastAPI simulator.

## 7. Guidelines for ML Model Training & Evaluation
1. **Exclude `capacity_increase` from Anomaly Positives**:
   - `capacity_increase` is an intentional capacity enhancement and network upgrade, not an operational failure or degraded state. Labeling it as an anomaly will introduce false positives into operational fault classifiers.
2. **Prevent Label Leakage**:
   - Under no circumstances should `fault_active`, `fault_type`, or `link_affected` be included in input feature sets. These columns contain ground truth injection labels.
3. **Cross-Validation & Splitting**:
   - Always partition training, validation, and test splits strictly by `scenario_id` (grouped split). Never perform a row-level random shuffle, which leaks time-series dynamics and topological context across splits.
